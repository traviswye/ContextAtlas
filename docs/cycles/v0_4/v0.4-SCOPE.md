## v0.4 thesis

**Make ContextAtlas production-usable end-to-end (install → atlas →
query → trust the output) for a solo developer on an existing
TypeScript / Python / Go codebase.**

Persona-narrowed deliberately. v0.3 proved the tool *works on three
pinned-SHA test repos under controlled conditions*. v0.4 hardens
the substrate so the same tool *works on a developer's actual
codebase* across the variance real-world environments introduce
(Node version drift, LSP server timing, non-standard test-file
layouts, atlas extraction on recent-not-pinned SHAs).

Other personas absorb later. Solo developer / new project (needs
ADR-creation pipeline) defers to v0.5+. Team workflow (needs git-
flow-for-atlases) defers to v0.5+. Additional language support
(Rust, .NET) demand-driven; defers to v0.7+.

Bounded validity confirmation absorbs in v0.4 because the launch
document needs a defensible answer to "did the answers get
worse?" Not full blind-grading methodology (that's v0.5+); enough
trial-variance evidence to say "v0.3 findings replicate."

The underlying question narrows from v0.3's "does extraction
sharpen?" to v0.4's "does the sharpened tool survive real-user
variance?"

## User-facing goal

The thesis above is the v0.4 *engineering* statement. The product
*goal* lives in [`ROADMAP.md`](ROADMAP.md) "What ContextAtlas Is
FOR" subsection and Travis's anchor framing preserved verbatim:

> The benchmark repo should only be used as a tool to better our
> main repo, whose ultimate goal is to be a production tool for
> developers to use with Claude Code to enable life improvements
> for Claude (the token burn, architectural context, etc).

v0.4 specifically delivers the production-tool surface a solo
developer encounters: install MCP, point at their TS/Python/Go
codebase, run extraction, query the resulting atlas via Claude
Code, get useful architectural-intent answers. Stream B's doctor
script is the diagnostic layer enabling self-service troubleshoot;
Stream C's bounded validity is the credibility layer enabling
launch-document claims to be defensible.

When tension surfaces during Stream A/B/C execution, ROADMAP wins;
this document amends to follow.

## Guiding principles (inherited + new)

All v0.1/v0.2/v0.3 guiding principles apply unchanged. The ones
that most constrain v0.4 decisions:

- **Evidence-gated upgrades.** Every v0.4 deliverable cites a v0.3
  finding, Step 16 process-hygiene observation, or scope-deferred
  v0.3 item that triggered it. No speculative scope.
- **Production-tool framing as primary thesis.** When a deliverable's
  shape is ambiguous between research-flavored and production-tool
  shapes, production-tool wins. Bounded validity confirmation is
  the explicit exception (research-shaped work absorbed for
  launch-document credibility).
- **Persona-narrowed scope.** Solo developer / existing codebase /
  TS-Python-Go is the v0.4 user. Scope decisions check against
  this persona, not the broader "any developer any codebase" goal.
- **Explicit deferral discipline.** v0.3's silent deferral of three
  claim-source items is the pattern v0.4 corrects. Items not
  shipped get explicit "defers to v0.5+ because X" stamps, not
  silent disappearance.
- **Capacity-permitting absorption with explicit triggers.**
  Methodology-hygiene items (B1 + B3 + A3) absorb into Stream A if
  Stream A core lands on schedule (rescope condition: by day 3 of
  v0.4 execution OR at $30 cumulative spend, whichever first).
- **Dogfood is acceptance test, not afterthought.** Stream B's
  contextatlas-on-itself dogfood IS the acceptance test for Stream
  A substrate-hardening + Stream A commit-message extraction. If
  dogfood fails, Stream A blockers surface; v0.4 doesn't ship
  until dogfood passes.
- **One-way migrations.** Atlas schema v1.3 stays unless commit-
  message extraction surfaces a need. Symbol ID format remains
  ADR-01 stable. No backward-compat cruft.
- **Bounded research absorption.** Stream C is rigor-for-launch-
  credibility, not rigor-for-research-paper. Cell selection
  bounded; trial count bounded; cost envelope bounded.

## Scope

v0.4 delivers three streams. Stream A (substrate hardening) is the
foundational stream; Stream B (dogfood + doctor script) tests it
via real use; Stream C (bounded validity confirmation) provides
launch-document credibility. Streams have natural sequencing — see
Sequencing section.

### Stream A — Substrate hardening + cost transparency + commit-message extraction

**Headline:** Make ContextAtlas's extraction + query substrate
robust against real-user variance. Five core sub-items + commit-
message extraction + cost-projection disclaimer; capacity-permitting
absorption of three methodology-hygiene items.

**Core sub-items (thesis-driving):**

- **B2 — LSP adapter timing-race robustness.** v0.3 Commit 1.5
  (`04f5b9d`) shipped a symptom fix (TS adapter `getDiagnostics`
  1s → 5s timeout) when tsserver cold-start exceeded the 1s
  polling ceiling on Node 22 / typescript-language-server 4.4.1 /
  typescript 5.9.3. The underlying issue (fixed-ceiling polling
  fragile across LSP-server timing variance) generalizes to
  Pyright + gopls. v0.4 deliverable: **bounded-poll + explicit
  readiness-signal pattern** replacing fixed-ceiling polling on
  all three LSP adapters. Implementation depth: poll until
  readiness signal received OR ceiling fires (raised ceiling
  acts as safety net, not primary mechanism). Per ADR-13
  (Pyright) + ADR-14 (gopls) amendments if the pattern affects
  documented behavior.

- **A4 — Directory-aware test-file exclusion.** v0.3 Stream B's
  `excludePattern` is filename-based (`test_*.py`, `*_test.go`,
  `*.test.ts(x)`); misses `tests/__init__.py`, `runtime-tests/`,
  `benchmarks/`-style directories. CLAUDE.md already flags this
  as "may need explicit config in a future version." v0.4
  deliverable: **directory-aware exclusion** via config-driven
  glob patterns (e.g., `tests/**`, `**/test/**`) in
  `excludePattern`. Default patterns per language adapter cover
  the common-case directories; user override via `.contextatlas/
  config.yaml`. Cost impact bounded (~$0.14 across three repos
  in v0.3 substrate; small but material on user repos).

- **A1 — Per-target ceiling defaults via priors-derived
  defaults.** Step 13 per-repo cost priors at the budget gate
  are RepoName-keyed; ceiling defaults still hardcoded to
  conservative values requiring manual raising per repo. v0.4
  deliverable: **plumb priors-derived defaults into the ceiling-
  default mechanism.** ~30 LOC extension per Phase 8 §9.2
  estimate. Result: doctor script + onboarding flows can show
  reasonable cost previews per user codebase without manual
  ceiling-tuning.

- **A2 — Per-target retry-overhead modeling.** Step 13 per-repo
  cost priors don't model retry probability; hono retry pattern
  in v0.3 was structural (large-prompt + LSP-heavy substrate;
  observed retry rate yielded $17.76 actual vs $7–10 projected
  per Phase 5 priors). v0.4 deliverable: **add retry-probability
  field to cost priors** with target-specific values from v0.3
  observed-retry data. Affects budget-gate accuracy on user
  repos with structural-retry-prone characteristics.

- **A7 — Cobra contamination drift root-cause investigation
  (bounded scope).** v0.3 cobra contamination rate +8.33pp vs
  v0.2 documented as v0.4 root-cause candidate. v0.4 deliverable:
  **surface-level trace inspection on the 6 v0.3-flagged cells
  vs the 4 v0.2-flagged cells.** Document finding. Fix lands
  ONLY if implementation ≤30 LOC + no test substrate change
  required; above-threshold defers to v0.5+ regardless of root-
  cause clarity. Prevents A7 from becoming Stream A hidden
  scope balloon.

**Commit-message extraction (P3 lock; bounded threshold-gated):**

- **Implementation:** git log parsing for architectural-intent-
  flagged commits (regex-based pattern matching: "design:",
  "arch:", "ADR-related" keywords; configurable per-repo
  patterns); claim extraction via existing `EXTRACTION_PROMPT`
  applied to commit-message corpus; atlas integration via
  `source: "commit:<sha>"` claim format alongside
  `"docstring:<path>"` + `"ADR-NN"` shapes.

- **Validation across three v0.3 substrate languages:** Re-extract
  cobra + httpx + hono atlases at pinned v0.2 SHAs with commit-
  message claims integrated. Per-repo claim-density measurement
  determines integration vs deferral.

- **Density threshold (Q3 lock — bimodal-aware):** Ships if
  ≥30 commit-derived architectural-intent claims per repo on
  AT LEAST 2 of 3 repos AND any single repo above 50. Below
  threshold → integration defers per Q3 partial-pass scenarios:
  - All 3 pass: ship 3 atlases with commit-message claims.
  - 2 of 3 pass + ≥50 ceiling: ship 2-3 passing atlases with
    integration; document failing repo.
  - Bimodal (1-2 pass with ≥50 ceiling): ship for cobra-class
    repos; document hono/httpx-class repos as commit-message-
    claim-free; defer enrichment for those repo classes to v0.5+.
  - All fail: document the finding; commit-message extraction
    available as opt-in tool but no atlas integration in v0.4;
    defer integration to v0.5+.

- **Re-extraction cost:** $5–15 per envelope estimate (substrate-
  hardening fixes + commit-message claims integrated; A4
  exclusion change affects extraction behavior, independently
  warranting re-extraction even if commit-message threshold
  fails).

**Cost-projection disclaimer (Q5 lock — 5 locations):**

Per Travis's launch-document disclaimer ("our cost projections
are high...actual API charges typically lower"), v0.4 ships
explicit disclaimer in user-facing surfaces. NOT a math
recalibration (pricing volatility makes maintenance a liability,
not a one-time fix); only a documentation/UX patch:

- `extract-benchmark-atlas.mjs` console output: disclaimer line
  pre-extraction explaining projections are conservative.
- `scripts/run-reference.ts` console output: same pre-run.
- `README.md`: cost framing block in "What's Implemented Today"
  or near install instructions.
- `CLAUDE.md`: amended cost framing in Current Version block.
- `RUBRIC.md` (benchmarks repo) cost-priors section: methodology
  caveat alongside the priors table.

Narrow exception: if a definite math bug surfaces during v0.4
dogfood (projection logic uses wrong token-counting model,
double-counts tokens, etc.), fix that bug. Don't go hunting.

**Capacity-permitting absorption (NOT thesis-driving):**

These items absorb into Stream A if core sub-items + commit-

execution OR at $30 cumulative spend, whichever first.

- **B1 — File-case-mismatch hygiene gap.** v0.3 Commit 1 surfaced

### Stream B — Dogfood + doctor script

**Headline:** Run the full extraction pipeline on contextatlas-on-
itself + ship a diagnostic-only doctor script as the foundation
piece of the v0.5+ developer onboarding pipeline.

**Dogfood — contextatlas-on-itself extraction:**

- **Scope (Q6 lock):** Full pipeline end-to-end. Extract atlas
  from contextatlas main repo; verify atlas.json schema valid +
  sentinel symbol present + claim count >0; run at least one
  concrete `get_symbol_context` query against contextatlas atlas
  yielding useful architectural-intent bundle for launch-doc
  material.

- **Concrete test query:** `get_symbol_context("OrderProcessor")`
  is a contextatlas-conceptual symbol from DESIGN.md examples
  but doesn't exist in the codebase. Use **a real load-bearing
  contextatlas symbol** for the dogfood query — candidate
  shortlist: `LspClient` (the v0.3-Stream-A LSP timing-race
  fix touches this), `runExtractionPipeline` (extraction-
  pipeline core), or `LanguageAdapter` (the conformance-suite
  abstraction). Final selection during execution; bundle quality
  + launch-doc material value drive the choice.

- **Output:** Concrete query result captured for launch-doc
  "How I would use this on my codebase" section material.
  Not a test artifact; a demonstration artifact.

**Doctor script — diagnostic-only foundation:**

- **Scope:** Self-check script at `bin/contextatlas doctor`
  (or equivalent CLI subcommand) reporting actionable findings
  on ContextAtlas configuration + state.

- **Checks (bounded list — diagnostic only, NOT remediation):**
  - Config present at `.contextatlas/config.yaml`.
  - Atlas exists at `.contextatlas/atlas.json`.
  - Atlas pinned SHA matches HEAD (or N commits behind).
  - Atlas schema version current (v1.3+ for v0.4).
  - LSP server installed + working (per language adapter; spawn
    test, response-within-timeout check).
  - Extraction-prerequisites present (ADR directory, docstring
    sources, commit-message corpus if commit-message extraction
    enabled).

- **Output format:** Structured report with PASS/WARN/FAIL per
  check + actionable next-step text on FAIL/WARN ("Atlas is
  17 commits behind HEAD. Run `contextatlas extract --update`
  to refresh.").

- **NOT in scope (deferred to v0.5+ developer onboarding pipeline):**
  Configuration helper (Claude-Code-prompted onboarding); ADR
  bootstrap (creating ADRs from prose if none exist); warm-up
  prompt automation; lifecycle / continuous-integration patterns
  (atlas-staleness watching; pre-commit hooks; per-session
  refresh).

**Acceptance test — Q2 lock (cobra HEAD):**

- Doctor script reports green on contextatlas-on-itself
  (substrate-hardening + dogfood loop closed).
- Doctor script reports green on at least one fresh extraction
  of an existing user codebase: cobra at HEAD (NOT pinned v0.2
  SHA `88b30ab8`).
- **Confirmation gate:** Cobra HEAD ≠ pinned v0.2 SHA at
  execution time. If equal (cobra hasn't moved), switch to
  httpx HEAD or pull cobra to a recent post-pinning SHA from
  spf13/cobra origin.

### Stream C — Bounded validity confirmation

**Headline:** Confirm v0.3's four named findings replicate within
trial variance under n=2 trials on 5 high-leverage cells. Output:
launch-document defensibly states "v0.3 findings replicate; full
quality-axis blind-grading methodology is v0.5+ scope."

**NOT full quality-axis methodology.** Bounded — rigor-for-launch-
credibility, not rigor-for-research-paper.

**Cell selection (Q1 lock — 5 cells, n=2, 10 trials):**

- **p4-stream-lifecycle (Phase 6 / httpx)** — Theme 1.2 fix
  anchor. v0.3 measurement: ca uses 6 calls / 32.9k tokens (vs
  v0.2's 14 / 60.8k); −57% calls / −46% tokens. n=2 confirms
  whether the 6-call result is replicable or single-run noise.
- **3 win-bucket cells, one per repo (Stream B docstring source
  sample):** one cell each from cobra / httpx / hono win-buckets.
  Cross-language replication confirmation. Cell selection during
  execution: highest-token-reduction cell per repo.
- **cobra c4-subcommand-resolution** — Theme 1.1 multi-symbol API
  closure validation. v0.3 measurement: beta-ca used multi-symbol
  shape with 2 of 3 named symbols matching. n=2 confirms
  multi-symbol API exercise pattern stable across trials.

**Asymmetric re-test depth — Theme 2.2 falsification NOT
rigorously re-tested.** Theme 2.2 (Phase 7 §5.3 cross-harness
asymmetry hypothesis FALSIFIED) is across-substrate not single-
cell, so n=2 on 5 cells doesn't directly re-test it. Bounded
approach: the 3 win-bucket cells (one per repo) provide
consistency-confirmation evidence on the falsification surface.
Scope-doc explicit framing: **"Theme 2.2 falsification finding
remains 'consistent with single-run result' under v0.4 bounded
validity rather than 'rigorously re-tested'; full hypothesis
revisitation per A6 deferred to v0.5+."**

**Trial methodology:**

- Each cell run independently 2x (10 total trials).
- Trial-variance measurement: tokens / calls / cost per trial;
  variance across trials reported alongside means.
- No prompt changes; no condition changes; only re-runs.
- v0.4 atlases (re-extracted in Stream A) used as substrate.
  Apples-to-apples vs v0.3 single-run on same prompts +
  same-shape atlases.

**Output:**

- Phase 8 supplement amendment OR new Phase 8.5 mini-synthesis
  (TBD during execution; absorb into existing supplement if
  small, separate doc if substantial).
- Variance table per cell: tokens / calls / cost across trials;
  confidence framing ("findings replicate within ±X%").
- Launch-document credibility line: "v0.3 findings replicate
  within trial variance; full quality-axis blind-grading
  methodology is v0.5+ scope."

**Cost (Q1 + budget lock):** ~$10–15. Cell-shape similar to
Phase 8 cells; 10 trials at $1–1.50/trial.

## Sequencing

Streams have natural sequencing — Stream A is foundational, Stream
B tests it, Stream C re-validates against the post-Stream-A
substrate.

**Stream A → Stream B → Stream C rationale:**

- **Stream A first because substrate hardening enables clean
  dogfood.** B2 (LSP timing-race), A4 (directory-aware
  exclusion), A1 (priors-derived ceilings), A2 (retry-overhead),
  A7 (cobra root-cause) all touch extraction or query behavior
  that Stream B exercises. Stream B running on un-hardened
  substrate would surface Stream A bugs as Stream B failures —
  attribution gets noisy. Stream A landing first cleans the
  signal.
- **Stream B second because dogfood surfaces Stream A findings
  via real use.** Running contextatlas-on-itself + doctor script
  acceptance test on cobra HEAD is the integration test for
  Stream A's substrate hardening. If Stream B fails, Stream A
  has bugs that need fixing before v0.4 ships. Sequencing
  ensures the failure-mode is Stream-A-localizable.
- **Stream C last because validity confirmation needs substrate-
  stable v0.4 atlases to re-test against.** Running n=2 trials
  on Stream A re-extracted atlases gives apples-to-apples
  comparison vs v0.3 single-run trials on same-shape atlases.
  If Stream C runs before Stream A re-extraction completes,
  the trial-variance measurement conflates substrate-shape
  variance with trial-variance.

**Within Stream A:**

- Substrate-hardening core sub-items (B2 + A4 + A1 + A2) before
  re-extraction. Re-extraction validates the substrate-hardening
  changes don't break extraction.
- A7 (cobra contamination drift root-cause) parallel with
  substrate-hardening core. Trace inspection doesn't depend on
  fixes landing first; if A7 surfaces a cheap fix (≤30 LOC),
  ship it before re-extraction.
- Commit-message extraction implementation parallel with
  substrate-hardening. Re-extraction tests both.
- Cost-projection disclaimer documentation can land any time;
  smallest scope; latest before v0.4 ship if not earlier.
- Capacity-permitting absorption items (B1 + B3 + A3) absorb
  AFTER core lands. Trigger: day-3 OR $30-spend gate.

**Reasonable execution order:**

1. Stream A core sub-items (B2 + A4 + A1 + A2 + A7 trace
   inspection + commit-message extraction implementation).
2. Stream A re-extraction (cobra → httpx → hono per Step 14

## Rescope conditions

v0.4 rescopes (not kills — rescopes) if:

- **Stream A LSP timing-race robustness can't generalize across
  three adapters cleanly.** If bounded-poll + readiness-signal
  pattern requires per-adapter divergence (each LSP server has
  different readiness semantics; pyright vs tsserver vs gopls
  disagree on what "ready" means), v0.4 absorbs the divergence
  IF total LOC stays bounded (~150 LOC across three adapters)
  OR descopes B2 to TS-adapter-only (the v0.3 Commit 1.5 anchor)
  pending v0.5 redesign. Default: absorb if pattern stays
  unified-with-per-adapter-config; descope if it would balloon
  to per-adapter implementations.

- **Q3 commit-message threshold fails entirely.** If no repos
  pass the bimodal-aware threshold, commit-message extraction
  ships as opt-in tool only (no atlas integration in v0.4).
  Stream A still ships substrate-hardening + A4 + cost
  disclaimer + capacity-permitting absorption. Launch-document
  claim narrows: "extracts from ADRs and docstrings; commit-
  message extraction available as opt-in tool, atlas
  integration v0.5+ scope." Honest narrowing; not a v0.4 kill.

- **Stream B dogfood surfaces Stream A blockers.** If
  contextatlas-on-itself extraction OR doctor-script-on-cobra-
  HEAD acceptance test fails, surface the failure mode to
  Stream A; fix and retry. v0.4 doesn't ship until dogfood
  passes. Recovery path: per-failure-mode investigation
  (extraction failure → Stream A bug; doctor-script failure →
  doctor-script implementation gap).

- **Stream C bounded validity reveals unexpected divergence.**
  If trial-variance > 20% on multiple cells (n=2 trials show
  >20% delta in tokens/calls/cost), the v0.3 single-run
  measurements are higher-variance than assumed. Recovery path:
  expand to n=3 on the divergent cells (additional ~$5–8 spend);
  document expanded scope; preserve "bounded validity" framing.
  If divergence > 50%, escalate — full quality-axis methodology
  may need to land in v0.4 not v0.5+.

- **Capacity absorption trigger fails.** If Stream A core hasn't
  landed by day 3 OR $30 cumulative spend, capacity-permitting
  items (B1 + B3 + A3) explicitly defer to v0.5+ with stamps.
  No silent absorption; explicit deferral preserves backlog
  discipline.

- **Cost envelope ceiling pressure.** If actual spend approaches
  $50 ceiling before Stream C completes, treat as signal to
  investigate rather than raise the cap. Possible causes:
  re-extraction retry-overhead higher than v0.3 baseline
  predicted; commit-message extraction per-call spend higher
  than docstring extraction; A2 retry-overhead modeling
  surfacing real-world variance the projection didn't capture.
  Recovery path: pause Stream C; investigate cost driver;
  resume with tighter Stream C cell selection (down to 3 cells
  / 6 trials / ~$6–9) if needed.

- **External-facing target evidence bar.** If during v0.4
  execution the launch-document drafting reveals a public claim
  that v0.4 evidence can't support rigorously, that claim
  doesn't ship — even if it would have been acceptable for an
  internal milestone. Per v0.3-SCOPE.md inherited guideline
  applied to v0.4: over-shipping accuracy is preferable to
  under-shipping credibility.

Per ROADMAP.md's `Rescope conditions` philosophy, applied to
v0.4 scope.

## Open questions (to resolve during v0.4)

1. **Doctor script CLI surface — subcommand vs separate binary?**
   Two shapes:
   - (a) `contextatlas doctor` subcommand on the existing CLI.
   - (b) Separate `contextatlas-doctor` binary.
   Default lean: (a) — simpler distribution; one binary; fits
   MCP-as-CLI shape. Resolve during Stream B implementation.

2. **Doctor script output format — text vs JSON vs both?**
   Plain text more user-readable; JSON more machine-parseable
   (downstream tooling could consume). Default lean: text-
   primary + `--json` flag for machine output. Resolve during
   Stream B implementation.

3. **Concrete dogfood query selection.** Stream B's contextatlas-
   on-itself dogfood query needs a real load-bearing symbol
   yielding useful bundle for launch-doc material. Candidate
   shortlist: `LspClient`, `runExtractionPipeline`,
   `LanguageAdapter`. Resolve during Stream B execution; bundle
   quality + launch-doc material value drive selection.

4. **Bounded-poll + readiness-signal pattern unified vs per-
   adapter.** Stream A B2 implementation question: does pyright
   surface a clean readiness signal? gopls? tsserver does (per
   v0.3 Commit 1.5 fix experience). If per-adapter divergence is
   significant, the rescope condition fires. Resolve during
   Stream A execution.

5. **Commit-message corpus filter scope.** Stream A commit-message
   extraction architectural-intent regex pattern: `design:`,
   `arch:`, `ADR-related` keywords are starting candidates. Per-
   repo configurable patterns? Default-set vs strict-set? Resolve
   during Stream A implementation; default conservative
   (false-positives worse than false-negatives — a non-
   architectural commit yielding a non-architectural claim
   pollutes the atlas).

6. **Phase 8.5 supplement vs amendment to existing supplement.**
   Stream C bounded validity output: small enough to amend
   `phase-8-trace-analysis-supplement.md`, or warrants a new
   `phase-8-bounded-validity.md`? Default lean: amendment if
   <100 LOC; new doc if more. Resolve during Stream C synthesis.

7. **v0.5 thesis selection.** v0.4 scope explicitly defers
   multiple must-ship-before-v1.0 backlog items to flexible
   v0.5–v0.99 placement. v0.5 thesis selection chooses from:
   developer onboarding pipeline (full minus doctor script
   foundation); task-shaped bundle queries (`why_does_this_fail`,
   `onboard_to_feature`, `audit_change`); Q3-deferred claim-
   source items (PR-description mining + README/docs/ parsing);
   full quality-axis blind-grading methodology (only if v0.4
   launch-doc credibility gap surfaces). Default lean: developer
   onboarding pipeline OR Q3-deferred items, both production-
   tool aligned. Resolve at v0.5 scope-doc drafting time based
   on v0.4 launch-document drafting surfacing OR community-
   evidence accumulation OR external user request shifting
   priorities.
