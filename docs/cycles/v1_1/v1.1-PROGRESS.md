## Key empirical findings from this cycle (preserved as substrate-record)

**Phase 0 spike validated all four spike-check predictions:**

1. **Endpoint surface clean** — all 6 LSP methods (documentSymbol,
   references, hover, definition, typeDefinition, diagnostic) work
   cleanly through csharp-ls wrapper.
2. **Pull-model diagnostics** (LSP 3.17 `textDocument/diagnostic`)
   — push-model `publishDiagnostics` returns 0; pull returns 3
   Roslyn diagnostics with CS error codes for Broken.cs. Parallel
   to ADR-21 (Ruby) pull-model; diverges from ADR-13/14 push-model.
3. **Symbol-kind taxonomy clean** — no .NET-specific divergence
   parallel to Ruby's kind-12-uniform. Records map to
   `SymbolKind.Class` (5) — LSP spec has no dedicated record kind;
   Roslyn pragmatic mapping.
4. **csharp-ls absorbs Roslyn custom protocol entirely** — zero
   custom notifications surfaced during init or any LSP method
   call. Wrapper presents clean LSP-spec interface; ContextAtlas's
   `lsp-client.ts` needs no Roslyn-specific protocol handling.

**Surfaced Phase 0 discipline-pattern observation:**

**Windows PATH-enrichment for dotnet tools.** First probe attempt
failed `Error: spawn csharp-ls ENOENT` because Bash/Git-Bash on
Windows doesn't have `%USERPROFILE%\.dotnet\tools` on PATH (only
PowerShell does; SDK installer configures PowerShell only). Pattern
parallel to ADR-21 `RUBY_BIN_DIRS` workaround + ADR-14 gopls "Go
binary must be on PATH" finding. Adapter substrate requirement +
doctor preflight item at Phase 5.2 pending.

**Major incidental finding — cohort repo language matrix:**

- `apis` repo: **100% .NET / C#** (814 .cs files; ASP.NET Core
  multi-project solution)
- `mobileapp` repo: **.NET MAUI cross-platform** (5,274 .cs files +
  small Swift 95 + Kotlin 94 sibling modules)
- SDK pin: .NET 10 SDK 10.0.203 (cohort-version anchor for ADR-22)

The .NET adapter unlocks **both** cohort repos (~6,000 .cs files
combined), not just backend. Original framing assumed mobile was
native Android/iOS; empirical confirmation showed .NET MAUI primary.

**A1/A2 fork lock with maintenance-tail caveat:**

A1 (csharp-ls wrapper) locked. csharp-ls is solo-maintained by
Saulius Menkevičius — NOT corporate-backed parallel to ruby-lsp
(Shopify). Three mitigations preserved at ADR-22:

1. A2 fallback path documented (Roslyn-direct adapter at v1.2+ if
   needed; custom-protocol substrate becomes adapter-internal
   rather than wrapper-delegated; no architectural rewrite).
2. Doctor staleness signal — warn when csharp-ls release age
   exceeds 12 months (v1.1.x candidate).
3. Minimum-version pin + major-version block — adapter accepts
   `csharp-ls >= 0.24.0, < 1.0.0`.

## Phase 4 close — substrate-record observations

**(i) Path β-parallel mid-substep adjudication for C# parameter-list-
in-name divergence.** Ruby Path β (c54ff7c) established cross-
adapter conformance harness flexibility for kind divergence
(`["function", "method"]`). C# Phase 4.3 surfaces a parallel axis:
the C# adapter explicitly encodes parameter lists into method
symbol names per Roslyn-overload-disambiguation convention
(`FormatGreeting(string name)` not `FormatGreeting`; csharp.ts
§listSymbols). Conformance harness functionSymbol matcher amended
to accept name-with-open-paren prefix in addition to exact match.
Zero regression in TS/Python/Go/Ruby suites — the OR-branch only
fires for languages that encode parens in names. Substrate-record
pattern: cross-adapter conformance harness flexibility is a
discipline pattern (Ruby precedent + C# precedent now); future
adapter authoring should anticipate language-structural-property
divergence at harness contract design surface, not retrofit.

**(ii) Path B substrate-continuity applied at Phase 4.1.** Ruby
6f9ae29 preserved Rails-flavored secondary substrate alongside new
canonical sample.rb. C# Phase 4.1 mirrored — Sample.cs authored
with Greeter+FormatGreeting; Consumer.cs amended with new Greeter
reference; existing User/IUserService/UserService/Analytics/Broken
+ Models/Services/Lib subdirectories preserved as probe-substrate-
record. Path B is now the established pattern for fixture
promotion when prior probe substrate has load-bearing empirical
coverage.

**(iii) PATH-enrichment helper re-uses adapter export.** Unlike
go.conformance.test.ts and ruby.conformance.test.ts which inline
their own enrichPath function, csharp.conformance.test.ts imports
the adapter's exported `enrichPathForDotnetTools()` directly.
Cleaner pattern — single source of truth for the candidate path
list; harness invocation is redundant-but-idempotent with the
adapter's internal call. Worth carrying forward to future adapter
authoring (Rust, Java, etc.) — export the enrichment function from
the adapter rather than duplicating in the conformance test.

**(iv) Phase 4 amendment count: 1 (conformance.ts Path β-parallel).**
ADR-22 amendment count remains 0 at Phase 4 close. Matches Phase 0
spike prediction (0-2 amendments; vs Ruby's 5). Conformance harness
amendment was anticipated by Ruby Path β precedent (Pattern 7
discipline working as designed — surfaced via empirical
implementation pressure at Phase 4.3 entry).

controls which languages get auto-detected by `contextatlas init`.

repo would flow to the new-project route at init time. This was
worth catching at Phase 5.1 surface-survey not at later cohort UX
testing — surface inventory discipline working as designed.

remains 0 at Phase 5 close. v1.1 cycle still tracking 0-amendment

substantively benefited from Phase 0 spike substrate.
