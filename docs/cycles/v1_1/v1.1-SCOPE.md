language, extending the TS/Python/Go/Ruby matrix established across

benchmarks repo persists as historical record and ad-hoc empirical
playground; it does NOT gate v1.1+ ships. Cycle-engineering
discipline carry-forward (Pattern 7 four-axis verification, pause-
and-surface vs verify-and-act, cross-role verification at
measurement-substrate entry) is how-we-work production-tool quality
discipline, not research methodology.

## §1 Cycle thesis

v1.1.0 ships a production-grade .NET/C# language adapter
(`CsharpAdapter`) against Roslyn LSP
(`Microsoft.CodeAnalysis.LanguageServer`), following the Ruby v0.9
Stream A precedent template. C# joins TS/Python/Go/Ruby as the 5th
supported adapter at the public-cohort surface.

**Why sole-focus.** Forced-sequence rationale per v1.1 cycle pre-
planning conversation: the dev repo (Expo/TS/RN) needs federated
access to the .NET backend atlas to surface API discovery + design-
decision claims during lightweight-app development. The .NET adapter
is the gate; federation (Shape 1, asymmetric consumer-model) is the
next ship and follows naturally once the adapter exists + the dev
repo has enough code to generate dogfood queries.

**Why scoped narrow.** v1.1.0 is the first production-tool cycle.
A focused sole-focus ship validates the production-tool cycle
cadence (2-3 weeks per adapter per Ruby precedent) without
compounding multi-feature scope risk. Federation lands as v1.1.x
once .NET is real.

## §2 Scope — in / out

### In-scope (v1.1.0 ship-bearing)

   verification that `Microsoft.CodeAnalysis.LanguageServer` surfaces

   substrate verification at cycle kickoff. Confirms or revises the

   precedent). Probe scaffold + .NET fixture + capability probes +
   ADR-22 authoring (probe-empirical-grounded) + cohort-version
   amendment if Roslyn version drift surfaces.
3. **Version anchor + type substrate** (Phase 2). LanguageCode +
   LANG_CODES additions for C# (short code likely `cs`). Cohort-
   version range anchor in ADR-22.
4. **CsharpAdapter implementation** (Phase 3; Substeps 3.1-3.8 per
   Ruby precedent).
5. **Conformance test substrate** (Phase 4; Substeps 4.1-4.3).
   Fixture promotion + K-2-ii probe substrate archival + conformance
   test scaffold + PATH-enrichment helper if Roslyn install variation
   warrants.
6. **Integration sweep** (Phase 5; Z-3 hybrid decomposition). Docs +
   init + excludePatterns at 5.1; doctor substrate for .NET
   environment checks at 5.2.
7. **Cycle close** (Phase 6). ADR-22 final + v1.1.0 tag + handoff
   substrate-record observations append.

### Out-of-scope (explicit; v1.1.x or beyond per `v1.1-2.0-ROADMAP.md`)

- **Multi-repo Shape 4 atlas-of-atlases.** v2.0 per roadmap.

  Roadmap Arc 3.

## §3 Prerequisites

**ContextAtlas v1.1.0 ship has no external prereqs.** Ship criteria:
code complete + tests pass + doctor surfaces correct C#/Roslyn
environment state + ADR-22 substantively complete + first-execution-
at-canonical-repo verification on a real C# project per Pattern 5.

**Travis-bearing personal prereq for dogfood validation** (separate
timeline from v1.1.0 ship):

- `/generate-adrs` runs locally against core app repo + backend
  (.NET) repo to produce ADR substrate that ContextAtlas can
  extract.
- Subsequent `contextatlas index` runs against backend repo (once
  .NET adapter ships) to produce backend atlas.
- Dogfood validation against three-repo product family happens once
  v1.1.0 ships + Travis's prereq atlases are extracted + federation
  v1.1.x lands.

This separation matters for cycle-discipline framing: v1.1.0 ships
when the adapter is production-ready, independent of Travis's
personal dogfood readiness. Empirical adapter validation happens via
existing TS/Python/Go/Ruby benchmark substrate + a new C# fixture
target (TBD at Phase 1 substep 2; minimal ASP.NET Core API + xUnit
project + EF Core or Dapper data access if structurally rich enough
for probe coverage).

## §4 Phase decomposition

Per Ruby v0.9 Stream A precedent template; adapted to .NET/Roslyn
specifics.

### Phase 0 — Roslyn probe spike gate (~1 day)

One-day empirical verification before committing the Ruby-anchored
2-3 week estimate. Spike scope:

- **LSP endpoint surface** — verify `documentSymbol`, `references`,
  `hover`, `definition`, `typeDefinition`, `textDocument/diagnostic`
  surface cleanly against Roslyn. Don't assume push-model-parallel-
  to-pyright-gopls (Ruby precedent surfaced pull-model surprise).
- **Symbol-kind taxonomy** — verify mapping to LSP standard kinds
  (or surface .NET-specific divergence parallel to Ruby's kind-6-
  uniform discovery).
- **Install variation breadth** — Roslyn ships with dotnet SDK;
  version-anchoring at probe phase prevents v0.9-style cohort-
  version gap.
- **Pattern 7 four-axis verification** at spike entry: structural-
  precedent / measurement-claim / version-anchor / dependency-
  constraint.

**Spike outcome adjudicates Phase 1 entry.** If spike surfaces
structural surprises (parallel to ruby-lsp kind-6 discovery), phase
decomposition revises before Phase 1 entry. Cheap insurance against
under-estimated cycle per v1_1-HANDOFF.md observation 19 + Pattern 6.

### Phase 1 — Probe substrate (Substeps 1-5)

1. **Probe scaffold** (~300-400 LOC). Mirror existing probe script
   structure from `docs/adr/ruby-lsp-probe/ruby-lsp-probe.ts`.
2. **.NET fixture authoring** — cohort-realistic; minimal ASP.NET
   Core API + xUnit test project + data-access layer if structurally
   rich enough.
3. **Probe implementation** — capability probes per ADR-22 target
   scope; probe-against-actual-channel-pattern discipline per
   `v1_1-INHERITANCE-SUBSTRATE.md`.
4. **ADR-22 authoring** — probe-empirical-grounded; expect 3-5
   substantive amendments within cycle per Ruby precedent and
   structural-complexity-correlates-with-amendment-frequency
   observation. Pre-allocate substep capacity.
5. **Cohort-version amendment** — probe re-execution against cohort-
   actual-version if Roslyn LSP version drift surfaces at Phase 1
   close (Path V-a precedent from v0.9 Phase 1 Ruby 3.3 → 4.0
   closure).

### Phase 2 — Version anchor + type substrate

- LanguageCode + LANG_CODES additions: `csharp` + short code `cs`
- ADR-22 §Cohort-version range surgical revision if Phase 1 cohort-
  version amendment surfaced version drift
- Probe substrate K-2-ii archival prep

### Phase 3 — CsharpAdapter implementation (Substeps 3.1-3.8)

Per Ruby v0.9 Stream A Phase 3 template:

- **3.1 Skeleton** — constructor, handlers, spawn, initialize,
  shutdown
- **3.2 listSymbols** — foundation for utility reuse
- **3.3 getSymbolDetails** — hover-based or structured-fields per
  probe finding
- **3.4 findReferences**
- **3.5 getDiagnostics** — push or pull per probe finding
- **3.6 getTypeInfo** — declaration-parse + usedByTypes scope
  decision per language-structural-property local-parseability
- **3.7 getDocstring** — forward-composition consumer of 3.3
  substrate if shared parsing
- **3.8 Adapter close + consolidation**

### Phase 4 — Conformance test substrate (Substeps 4.1-4.3)

- **4.1 Fixture promotion** — probe fixture → canonical harness
  fixture
- **4.2 Probe substrate archival** — K-2-ii consolidated
  subdirectory `docs/adr/csharp-roslyn-probe/`
- **4.3 Conformance test scaffold** — wire shared harness + Path
  P-1 PATH-enrichment helper if Roslyn install variation warrants

### Phase 5 — Integration sweep (Z-3 hybrid)

- **5.1 Docs + init + excludePatterns** — .NET conventional
  excludes (`bin/`, `obj/`, `*.user`, `.vs/`, `packages/`)
- **5.2 Doctor C# environment check surface** — dotnet SDK version,
  Roslyn LSP availability, project-system detection (`.sln`/`.csproj`),
  PATH variation if Roslyn LSP not on PATH after dotnet install

### Phase 6 — Cycle close + tag

- ADR-22 final amendment consolidation
- v1.1.0 version bump + annotated tag body + release-notes substrate
- Substrate-record observations append to next-cycle HANDOFF
- Full test suite + lint + typecheck before tag; doctor smoke-test
  on a real C# project per Pattern 5 first-execution-at-canonical-
  repo verification

## §5 Cycle-discipline carry-forward

How-we-work discipline patterns inherited from v0.8/v0.9 closes per
[`v1_1-HANDOFF.md`](../../../v1_1-HANDOFF.md):

- **Pattern 7 four-axis verification + 5a/5b sub-decomp** at every
  probe-phase + ADR-authoring + adapter implementation entry surface
- **Pause-and-surface vs verify-and-act discipline** (`b6ea824`
  canonicalization)
- **Cross-role verification at measurement-substrate entry**
  (Pattern 6 + observation 19) — Roslyn probe spike entry needs
  both lead institutional memory and dev fresh-read
- **Substep-bounded ship-commit discipline** — one commit per
  substep; mid-substep surgical revisions ship as separate commits
- **Execution-discipline (staging-set verification)** —
  `git status --short` empirical check before commit; commit-via-
  `-F` file pattern for bodies with apostrophes
- **First-execution-at-canonical-repo verification** (Pattern 5) —
  ship readiness includes real C# project smoke test, not just unit
  tests
- **K-2-ii consolidated probe substrate archival** —
  `docs/adr/csharp-roslyn-probe/` at probe-phase close
- **Skip-with-rationale pattern** for integration-sweep surfaces
  deliberately not touched
