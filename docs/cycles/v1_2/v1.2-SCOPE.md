## §1 Cycle thesis

v1.2.0 ships federation Shape 1: a consuming repo with its own
local atlas reads N read-only foreign atlases registered via
`.contextatlas.yml`. The three MCP tools (`get_symbol_context`,
`find_by_intent`, `impact_of_change`) fan out retrieval across
local + foreign atlases at query time without breaking ADR-02's
zero-query-time-API-call invariant. Foreign symbols are surfaced
with repo-prefixed IDs; local stays unprefixed.

**Why federation Shape 1 first.** Travis cohort surface-direct:
the new dev repo (Expo / TS / RN; scaffolding now) is built on
top of the apis backend (.NET; atlas extracted at v1.1 cohort
dogfood close). Cross-repo atlas consumption is the gating
requirement for development-time API discovery + design-decision
claim surfacing. Without federation, the dev repo has no
substantively-useful atlas integration during development;
WITH federation, it inherits the apis substrate as queryable
context.

**Why scoped to Shape 1 only.** Shape 2 (workspace concept) and
Shape 4 (atlas-of-atlases / merge-safety) add substantive complexity
(workspace YAML; umbrella ADR convention; cross-repo claim type).
Shape 1 ships the load-bearing federation primitive — read-only
consumption — that proves the architecture without ballooning
scope. Shapes 2 + 4 land naturally on top once Shape 1 is real.

## §4 Phase decomposition

Per v1.1 Stream A precedent template; adapted to federation Shape 1
specifics.

### Phase 0 — Federation Shape 1 spike gate (~1 day)

One-day empirical verification before committing the cycle estimate.
Spike scope:

- **Foreign atlas readability** — verify `.contextatlas/atlas.json`
  from the apis repo loads cleanly at the dev repo's MCP server
  process. Schema-version compatibility (apis atlas at v1.4; dev
  repo at v1.4+).
- **Symbol ID prefix format** — three candidate formats benchmarked:
  - Option A: `sym:apis:cs:Services/UserService.cs:GetByIdAsync`
    (repo-prefix as second segment)
  - Option B: `apis::sym:cs:Services/UserService.cs:GetByIdAsync`
    (repo-prefix as outer wrapper)
  - Option C: `sym:cs@apis:Services/UserService.cs:GetByIdAsync`
    (repo-prefix as language-tag annotation)
  Phase 0 outcome locks the format at ADR-01 amendment authoring
  (Phase 1).
- **MCP retrieval-layer cost** — measure query latency overhead
  for federated reads (single local + 1 foreign atlas) vs local-
  only baseline. Identifies any unexpected I/O or parsing
  bottlenecks before Phase 3 implementation.
- **ADR-05 amendment shape** — config-section design adjudication
  (file-path vs clone-path; explicit-naming vs auto-discovery).
- **Pattern 7 four-axis verification** at spike entry: structural-
  precedent (Ruby + C# adapter ship patterns); measurement-claim
  (federation cost overhead vs local-only baseline); version-anchor
  (atlas schema v1.4); dependency-constraint (preserves ADR-02
  zero-query-time-API-call invariant).

**Spike outcome adjudicates Phase 1 entry.** If spike surfaces
structural surprises (parallel to ruby-lsp kind-6 discovery), phase
decomposition revises before Phase 1 entry. Cheap insurance against
under-estimated cycle per v1_1-HANDOFF.md observation 19 + Pattern 6.

### Phase 1 — ADR substrate (Substeps 1-5)

1. **ADR-01 additive amendment** — repo-prefixed foreign symbol ID
   format locked per Phase 0 spike adjudication. Local stays
   unprefixed (preserve `sym:<lang>:<path>:<name>`).
2. **ADR-05 additive amendment** — `foreign_atlases` config section
   schema; preserves single-flat-YAML invariant (no inheritance
   chains); explicit allowlist with no auto-discovery (cohort opts
   in).
3. **ADR-23 authoring** — federated query retrieval-layer semantics:
   - Local-first retrieval (search local atlas before fanning to
     foreign).
   - Foreign-symbol surfacing with repo-prefix marker so consumer
     agents see cross-repo provenance.
   - Cost-bounded fan-out (max N foreign atlases; default cap TBD).
   - ADR-02 invariant preservation (no API calls at query time;
     reads only precomputed substrate).
4. **Two-atlas conformance fixture authoring** — minimal TS local
   atlas + minimal C# stub foreign atlas at
   `test/fixtures/federation/{local,foreign}/`. Structurally rich
   enough to exercise all three MCP tools across the local/foreign
   boundary.
5. **Cohort-version compatibility lock** — atlas schema v1.4 (current)
   confirmed as foreign-readable; future schema versions inherit
   forward-compatibility discipline (foreign atlas at older schema
   version is still readable; at newer schema version the consumer
   warns at doctor surface).

### Phase 2 — Type substrate (Substeps 1-3)

1. `ContextAtlasConfig.foreign_atlases` field + parser updates +
   validation.
2. `FederatedSymbol` + `FederatedAtlas` types in `src/types.ts`.
3. Atlas schema additive extension (if needed) — likely no schema
   change at consumer atlas; foreign-atlas references live only in
   config, not in atlas.json.

### Phase 3 — Federation implementation (Substeps 3.1-3.7)

Per v1.1 Stream A Phase 3 template:

- **3.1 Foreign atlas loader** — read-only `loadForeignAtlas(path)`
  returns parsed FederatedAtlas; idempotent caching keyed on file
  mtime; schema-version validation.
- **3.2 Foreign symbol resolver** — `resolveForeignSymbol(id,
  atlases)` parses repo-prefixed ID; routes to correct foreign
  atlas; returns Symbol record with provenance marker.
- **3.3 `get_symbol_context` federation extension** — accept
  repo-prefixed IDs; fan out to foreign atlas when ID has prefix;
  preserve local-first behavior for unprefixed IDs.
- **3.4 `find_by_intent` federation extension** — query each foreign
  atlas's intent registry; merge results with repo-prefix surfacing;
  cost-bounded fan-out per ADR-23.
- **3.5 `impact_of_change` federation extension** — cross-atlas
  reference resolution for symbols that have foreign-atlas consumers.
- **3.6 Adapter close + consolidation** — header doc + integration
  smoke test against two-atlas fixture.
- **3.7 C# symbol resolver name-prefix matching** (carried v1.1
  investigation candidate) — extend `resolveCsharpSymbol` to accept
  bare-name OR name-with-paren-prefix matching parallel to v1.1
  Phase 4 Path β-parallel conformance harness amendment. Validates
  via re-extraction against apis substrate (expected: substantively
  lower unresolved_candidates ratio).

### Phase 4 — Conformance test substrate (Substeps 4.1-4.3)

- **4.1 Fixture promotion** — Phase 1 fixture finalization for
  cross-adapter conformance harness coverage.
- **4.2 Conformance harness extension** — federated query
  conformance tests for each MCP tool; test seam pattern parallel
  to existing `runConformanceSuite` substrate.
- **4.3 Two-atlas integration smoke** — wire conformance against
  `test/fixtures/federation/`.

### Phase 5 — Integration sweep (Z-3 hybrid)

- **5.1 Docs + init + config examples** — README + DESIGN +
  ROADMAP + example `.contextatlas.yml` showing `foreign_atlases`
  section; init scaffold prompts for foreign atlas registration
  (optional; can skip and add manually later).
- **5.2 Doctor `foreign_atlas` check category surface** — new
  doctor checks: existence (file path resolvable), parseability
  (valid JSON + schema-version), staleness signal (foreign atlas
  `extracted_at_sha` vs foreign repo's actual HEAD if reachable —
  scoped narrow at v1.2.0; full staleness reconciliation v1.3+

### Phase 6 — Cycle close + tag

- ADR-01 / ADR-05 / ADR-23 final amendment consolidation.
- v1.2.0 version bump + annotated tag body + release-notes

## §7 Risks + mitigations

**(i) Atlas schema-version forward-compatibility risk.** Foreign
atlas at schema version older than consumer's current schema —
must still be readable (additive-amendment discipline). Foreign
atlas at newer schema version — consumer warns at doctor surface
("upgrade contextatlas or use older foreign atlas"). Mitigation:
explicit schema-version compatibility test at Phase 4 conformance
substrate.

**(ii) Foreign-atlas staleness risk.** Apis atlas snapshot at
extracted_at_sha=X; apis repo has advanced to HEAD=Y; consumer atlas
references stale apis claims. Mitigation: doctor staleness signal
(SHA-diff check if foreign repo path is reachable); cohort-UX
guidance ("re-pull foreign repo + re-clone foreign atlas after
upstream changes"). Full staleness reconciliation (auto-detect +
auto-fetch newer atlas) deferred to v1.3+ per scope-narrowing.

**(iii) MCP retrieval-layer cost overhead risk.** Federation fans
out reads across N atlases; query latency could multiply with N.
Mitigation: cost-bounded fan-out per ADR-23 (default cap = 5
foreign atlases; configurable); Phase 0 spike measures empirical
overhead vs local-only baseline; tunable cap surfaces in
`.contextatlas.yml`.

**(iv) Symbol-ID prefix format breakage risk.** Choosing wrong
format at Phase 1 forces ADR-01 re-amendment + cohort migration.
Mitigation: Phase 0 spike benchmarks three candidate formats
empirically; outcome locks format with rationale captured at ADR-01
amendment; format change at v1.3+ would be a major version bump
per ADR-01 §Decision "format MUST NOT change in MVP or v0.x
releases" extended to v1.x with explicit migration note.

**(v) ADR-05 amendment risk — slippery-slope to inheritance
chains.** Adding `foreign_atlases` section opens the door to
"why not inheritance chains too?" cohort pressure. Mitigation:
ADR-05 amendment text explicitly preserves single-flat-YAML
invariant; foreign atlases are explicit allowlist NOT inheritance
NOT cross-repo config-fragment merging; the line stays drawn.

**(vi) v1.1 investigation candidate (C# resolver name-prefix
matching) overlap risk.** If Phase 3.7 expands substantively, it
could substantively expand cycle scope. Mitigation: Phase 1 entry
re-adjudicates 3.7 scope; if expansion warranted, split into
substep 3.7-α (canonical) + 3.7-β (extended); ship 3.7-α at
v1.2.0 with 3.7-β deferred to v1.2.x if cohort signal warrants.
