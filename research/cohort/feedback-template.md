# ContextAtlas v0.6 Cohort Feedback Template

**Audience:** Early-access cohort participants. Thank you for
spending time with the tool — your feedback shapes v0.7 design +
v1.0 launch substrate substantively.

**What this template captures:** structured feedback isolating
three failure modes (natural-routing failure / tool-description
failure / missing-functionality failure) per cohort-process
discipline at v0.6-SCOPE.md §Stream C. Cohort sessions surface
what atlas tools do well + what frictions surface + where
ContextAtlas falls short of expectation.

**What this template does NOT capture:** observability log
data is auto-captured via `--observe` flag opt-in (per ADR-20
cohort observability contract; data retention + participant
rights documented there). This template covers the human-
written feedback complementing observability data.

**Two-layer consent:** filling out this feedback template is
voluntary at every point; observability data capture (per
ADR-20) is governed separately by your `--observe` flag opt-in
choice. You can fill some sessions and skip others, or stop at
any time.

**Time expectation:** ~5-10 minutes per session feedback +
~30-45 minutes post-trial structured feedback. Sparse-is-OK;
honest sparse beats forced verbose.

**Submission:** [TBD at Step 6.4 recruitment infrastructure]

## Per-session feedback (fill when atlas-relevant)

You don't need to fill this template after every Claude Code
session — fill after sessions where atlas tools were relevant
to the work (or were expected to be and weren't). Sessions
doing unrelated work (e.g., coding without atlas-relevant
queries) don't need feedback entries.

**Session ID:** _(auto-generated by `--observe`; cross-reference
to observability log entry)_

**Session date:** _____

**Atlas tool invocation outcome:**

- [ ] Claude correctly invoked an atlas tool
      (`get_symbol_context`, `find_by_intent`, or
      `impact_of_change`)
- [ ] Claude did NOT invoke an atlas tool when expected (atlas
      would have helped but Claude didn't reach for it)
- [ ] Claude invoked an atlas tool that produced unhelpful or
      wrong results
- [ ] Mixed / partial — some invocations helpful + some
      missing/wrong
- [ ] No atlas-relevant work this session (skip remaining
      session-feedback fields)

**Usefulness rating** (when atlas WAS invoked):

- [ ] Very useful — atlas response substantively helped the task
- [ ] Useful — atlas response added value, some friction
- [ ] Neutral — atlas response present but task could have been
      done without it
- [ ] Unhelpful — atlas response distracting or off-target
- [ ] Wrong — atlas response factually incorrect or misleading

**Free-text: missed invocations**

> Where would atlas have helped that Claude didn't use it? What
> task were you doing? What did you expect Claude to do
> instead? (Examples: "Asked Claude about a symbol's
> implementations; Claude grep'd source instead of using
> `get_symbol_context`")

_____

**Free-text: wrong invocations**

> Where was atlas used but produced unhelpful or wrong results?
> What did you ask? What did atlas return? What did you expect?

_____

**Anything surprising or noteworthy this session?**
