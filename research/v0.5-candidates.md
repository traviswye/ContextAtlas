**Status:** Authored during v0.4 Step 10 (synthesis). Locks the

Categorized + numbered consecutively across categories so v0.5

**Last updated:** 2026-04-29.

## Substrate gaps (would-be-fixes-if-time)

### 1. `classifyError` catch-all conflates JSON-parse exceptions with API errors

**Surfaced:** v0.4 Step 5 httpx 24-error investigation.

**Problem:** `classifyError` catch-all logs JSON-parse failures
identically to genuine Anthropic API errors. Root cause masked
during the Step 5 investigation; required a 3-sample diagnostic
to disambiguate transient API errors from response-shape errors.

**Fix shape:** Dedicated `ParseError` class + classifier branch
that distinguishes parse failures (deterministic; recheck the
LLM output shape) from API failures (transient; retry with
backoff).

### 2. `extractDocstringsForFile` non-idempotent at symbol level

**Surfaced:** v0.4 Step 7 dogfood extraction.

**Problem:** Re-running extraction on a file with renamed
symbols produces stale-symbol claims that don't get garbage-
collected. Symptom: atlas grows over successive extractions
even on stable corpora.

**Fix shape:** Symbol-id-keyed idempotency at extraction time
(not write time). Re-extracted file's claim set replaces the
prior claim set keyed by `(file_path, symbol_id)`.

### 3. `pipeline.ts` Stage 5 deletion handling defeats Stream C idempotency

**Surfaced:** v0.4 Step 7 dogfood extraction (cross-cuts with
candidate 2).

**Problem:** Stream C claim records survive symbol deletion
because Stage 5 deletion handling treats Stream C as opaque.
Distinct from candidate 2 in that the deletion path is the
break, not the re-extraction path.

**Fix shape:** Claim-source-aware deletion sweep at Stage 5;
Stream C records GC'd alongside symbol records for deleted
symbols.

### 4. `buildBundle` requires adapter in atlas-only mode

**Surfaced:** v0.4 Step 8 doctor work (limited-mode design).

**Problem:** When atlas is committed and queries are pure-atlas,
adapter spawn is dead weight — adds ~500ms per query for no
information gain. Surfaced via doctor's limited-mode work but
not addressed in v0.4 (out of doctor's diagnostic-only scope).

**Fix shape:** Lazy-spawn adapter only when query needs LSP-
live data (e.g., diagnostic resolution; recently-edited file
re-symbolization).

## Feature gaps (extension scope)

### 5. Filter-shape vs content-richness — three sub-candidates

**Surfaced:** v0.4 Step 4 + Step 5 commit-message empirical
finding.

**Problem:** Stream C filter is conventional-commits-prefix-
anchored. Substrate that doesn't follow that convention (e.g.,
ContextAtlas's own step-stamped commits at 5/129 = 3.9%
selectivity vs design-target ~30%) under-captures. The filter
design is correct *for its target corpus*; corpus-fit is the
gap.

**Fix shape (three sub-candidates):**

- **5a — Replace-mode filter.** Drop conventional-commits
  prefix-anchor; switch to body-anywhere semantic match for
  non-conventional corpora. Lowest-cost option; risk is
  selectivity overshoot.
- **5b — Content-density-aware filter.** LLM-judged "is this
  commit message architecturally informative" gate; small-N
  cost trial first to bound spend.
- **5c — Per-repo filter customization.** `.contextatlas.yml`
  `commit_filter` block; opt-in advanced config. Highest-
  ergonomic-cost option; defers the corpus-fit question to
  the user.

**v0.5+ planning:** cost trial decides which sub-candidate has
the best evidence-to-effort ratio. Likely 5a if evidence
permits; 5b if 5a overshoots.

### 6. Deep LSP health check

**Surfaced:** v0.4 Step 8 doctor design.

**Problem:** Doctor (Step 8) does shallow spawn-+-initialize
check. Misses adapter regressions like gopls workspace-load
failure on `go.mod`-less directories — failures that surface
only when an actual symbol query is attempted.

**Fix shape:** Full `initialize → didOpen → diagnostic-arrival
→ shutdown` sequence with actual symbol traversal in doctor's
LSP category. Catches regressions doctor currently misses.

## Process improvements

### 7. `parser.test.ts` schema-driven test data generation

**Surfaced:** v0.4 Step 2 + Step 4 (recurrence).

**Problem:** Hardcoded valid-keys regex needs hand-updating
every time `validateExtraction` adds a field. Recurred at
Step 2 and Step 4; will recur on every future field addition.
Test-as-mirror-of-implementation is brittle by construction.

**Fix shape:** Replace hardcoded regex with schema-derived
test fixtures (introspect the schema; generate valid-key list
at test-build time; assert dynamically). Eliminates fragility
recurrence.

### 8. Pipeline-integration scope confusion discipline (formalization)

**Surfaced:** v0.4 Step 5 + Step 7 (recurrence; already
informally documented).

**Problem:** When wiring a new claim source into an existing
pipeline (e.g., Stream C → existing extract orchestrator),
absent precedent-location verification leads to drift between
the new integration and the existing pattern. Saved at least
one rework cycle each time the discipline was applied.

**Fix shape:** Lift the discipline to CLAUDE.md as a checked
invariant for new claim sources: "Before drafting integration
for a new claim source, read the precedent integration
verbatim; integration shape is symmetry with the precedent,
not symmetry-by-default."

## Methodology hardening (v0.4 cycle deferred)

### 9. Calls quantization → call-bucket reporting

**Surfaced:** v0.4 Step 9 §8.4 supplement amendment.

**Problem:** Step 9 measured 28.6% median calls-Δ across
n=2 trials; this looks alarming but reduces to ±1 call on
small-N cells (e.g., 6→7 = 14.3%; 4→5 = 22.2%). Quantization
noise, not behavior change.

**Fix shape:** Switch variance reporting to call-buckets
(1-3 / 4-7 / 8+) for cells with low-N trial counts.

### 10. Quality-axis blind-grading methodology

**Surfaced:** v0.4 scope-doc Step 9.4 explicit deferral.

**Problem:** v0.4 measures token-cost replication but not
output-quality replication. Whether output quality also
replicates within trial variance is v0.5+ scope.

**Fix shape:** Graded-output protocol + double-blind LLM-judge
pipeline + judge-agreement statistics. Substantial v0.5+
investment; not a quick win.

### 11. Full statistical bounded-validity (n>2)

**Surfaced:** v0.4 Step 9 §8.6 limitations.

**Problem:** Step 9 ships n=2; provides bounded-validity per
scope-doc lock but is not statistical replication. Mean,
median, and CI estimates require larger N.

**Fix shape:** n≥5 per cell with CI computation; full-matrix
replication (not finding-anchored cell selection). Cost
projection: ~5x Step 9 cost (~$10-12 script-projected).

### 12. Adaptive per-repo cost ceilings

**Surfaced:** v0.4 Step 3 priors-derived defaults design.

**Problem:** Step 3 RETRY_OVERHEAD_V0_3 + cost-priors are
static. Over time, observed cell costs drift from priors
(per-repo doc density, per-repo commit conventions).

**Fix shape:** Adaptive priors update from observed cell costs
across the matrix run; persisted as `.contextatlas-priors.json`
or similar.

### 13. Self-use ContextAtlas-as-MCP onboarding pipeline

**Surfaced:** v0.4 Step 7 dogfood extraction.

**Problem:** Step 7 dogfood produces atlas; integration into
Claude Code's MCP config is manual. Onboarding flow is
fragmented across `npm install` + extract script + manual
MCP-registration + first-query smoke test.

**Fix shape:** `contextatlas init` command + auto-MCP-
registration + first-query smoke test. Most natural placement:
v0.5 thesis-primary per ROADMAP framing.

## Cross-cutting notes

**Cost-projection-vs-platform-billing systematic discrepancy
observed across v0.4 cycle.** Script-projected costs ran ~3x
higher than platform-billed actuals (cache-discount effect on
warm `EXTRACTION_PROMPT` prefix). v0.4 Q5 lock disclaimed
projection language across 5 user-facing surfaces; adaptive
correction is candidate 12 territory if drift is observed
beyond the disclaimer.

**Three-measurement noise-floor convergence (~4-13%).**
Documented in `phase-8-trace-analysis-supplement.md` §8.5
(benchmarks repo). Independent dimensions (extraction-side,
matrix-run tokens, cost) all land in the same band; substantiates
bounded-validity claim. Full statistical methodology (candidate
11) is the next escalation.

## How v0.5 scope-doc uses this list

**Not all candidates ship in v0.5.** v0.5 thesis-primary is
likely **candidate 13 (self-use onboarding pipeline)** per
ROADMAP framing. Other candidates land per evidence-and-
capacity intersection at per-version scope-doc drafting time.

**Per-candidate placement decision criteria:**

- Substrate gaps (1-4): generally land alongside whichever
  v0.5+ thesis touches the affected surface. Candidate 4
  pairs naturally with candidate 13.
- Feature gaps (5-6): evidence-gated. Candidate 5 needs cost-
  trial evidence; candidate 6 needs adapter-regression
  surfacing.
- Process improvements (7-8): land opportunistically alongside
  any commit touching the relevant code paths.
- Methodology hardening (9-13): land when launch-doc credibility
  or community evidence demands the rigor escalation.
