## v0.6 thesis

**Generate empirical substrate for v0.7 production-launch design
work via early-access onboarding pipeline cycle.** v0.6 ships
install + doctor + config walkthrough + atlas creation + smoke test
pipeline-mechanics under early-access cohort exposure (minimum bar
1-2 Travis network developers; ideal range 5-15; private invitations;
controlled exposure); generates cohort UX feedback + tool-description
observability + targeted matrix-replication substrate + self-use
observations + B13-flag usage data — all consumed at v0.7
production-launch design work.

The cycle architecture exists specifically to avoid the v0.5-Step-6-
mistake-pattern at multi-cycle scale: v0.5 Step 6 calibrated rubric
anchors in single-mode operating regime; Step 8 paired-mode operating
regime surfaced different rubric properties than Step 6 calibration
anticipated. The lesson generalized across cycles: design-without-
empirical-operating-regime produces conclusions that reverse when
operating regime arrives. v0.7 designing-in-vacuum without v0.6
cohort empirical signal would repeat the pattern at cycle-architecture
level rather than substep-calibration level.

Cycle-thesis is **substrate-generation, not feature-completion**.
v0.6 doesn't ship maximally-featured production tool; v0.6 ships
pipeline-mechanics that work under cohort exposure + instrumentation
to capture cohort signal informing v0.7 design. Strategy B-with-
explicit-launch-staging: v0.6 = early-access cycle; v0.7 = production-
launch-substrate cycle (onboarding-completion + matrix-completion +
external trial + task-shape API); v0.8 = potentially-needed cycle
if v0.7 weight calibration triggers cycle splitting; v1.0 = public
production launch with all ship-gate criteria closed.

Cross-stream coherence check: Stream A ships pipeline-mechanics
that cohort exercises; Stream B validates methodology rigor in
parallel via targeted matrix-replication subset; Stream C captures
cohort exposure under structured feedback template + tool-description
observability. All three streams serve substrate-generation-for-v0.7
thesis; methodology-coherent across cycle-architecture / scope-bounding
/ procedural-pattern dimensions per Phase 2 cross-item coherence
check.

## User-facing goal

A developer with a TypeScript / Python / Go codebase + existing
ADRs runs:

```
$ npm install -g contextatlas
$ contextatlas init
```

and walks through:
1. Doctor script verifies repo state (existing-repo vs new-project
   detection; ADR / code / README / DESIGN.md / language / git
   substrate independent detection per H5 multi-dimension logic)
2. Config setup walkthrough (with optional flags exposing B13
   architectural choice: Anthropic API + Claude Code [default; current
   dual-dependency] vs Claude Code only [proposed single-dependency
   path])
3. Atlas creation (extracts ADRs into atlas; assumes ADRs exist OR
   user has manually added them per doctor's missing-ADR guidance)
4. Doctor re-run for verification
5. First smoke-test query (known-symbol `get_symbol_context` call
   demonstrates tool works end-to-end under user's repo)

After install completes, developer's Claude Code session can
productively invoke ContextAtlas MCP tools (`get_symbol_context`,
`find_by_intent`, `impact_of_change`) during natural conversation
without manual config-file editing.

**Cohort scope:** minimum bar 1-2 developers for substrate generation;
ideal range 5-15 developers based on Travis network availability +
early-access willingness; cohort recruitment runs during v0.6 cycle
execution Stream C work per Item 6 recruitment infrastructure
shipping at v0.6. Selection biased toward repos with existing ADRs
since v0.6 doesn't ship H2 ADR generation; missing-ADR repos receive
explicit doctor message ("ContextAtlas requires ADRs; v0.6 doesn't
auto-generate; please add ADRs manually then re-run doctor"); cohort
feedback template captures missing-ADR-encountered cases as v0.7 H2
design substrate.

**v0.6 cohort exposure produces five substrate dimensions for v0.7
design consumption:**
1. Cohort UX feedback on install-flow / config-walkthrough / smoke-
   test mechanics (per Item 5 cohort feedback template)
2. Tool-description observability data: which MCP tools Claude
   routes-to during natural conversation; isolates tool-description-
   tuning targets for v0.7
3. Targeted matrix-replication subset substrate (3 cells testing
   v0.5 tier-gradation generalization at specific points per Item 3)
4. Self-use observations during v0.6 cycle execution per Item 4
   hybrid capture (progress-log entries + lightweight `research/v0.6-
   self-use-log.md` append-when-observed)
5. B13-flag usage substrate informing v0.7 architectural decision
   per Item 2 reconsider lock (which path users default to; what
   friction each produces; does single-dependency reduce setup
   friction substantively)

Goal is **NOT** v0.6 ships maximally-featured production tool. Goal
**IS** v0.6 ships pipeline-mechanics + instrumentation generating
empirical substrate for v0.7 design without v0.7-designing-in-
vacuum.

## Guiding principles (inherited + new)

**Inherited from v0.5 + prior cycles:**

- **Atlas is portable, reviewable, committed artifact** (ADR-06)
- **No query-time LLM calls** (ADR-02)
- **Evidence-gated upgrades** — features ship when benchmarks show
  need, not when they sound good
- **Signal fusion at query time, not ingest time** — sources stay
  independent at storage; queries compose
- **MCP protocol correctness** — stable contract for external
  consumers
- **Do it right, not descope for timeline** — multi-release project;
  individual cycle scope isn't determined by external deadlines
- **Dogfood always** — ContextAtlas indexes itself; used during own
  development; B17 v0.6 self-use logging hybrid capture per Item 4
- **One-way migrations** — atlas schema, symbol ID format, MCP tool
  shapes forward-only

**New at v0.6:**

- **Flexibility-as-feature design principle (Travis lock; carries
  forward to v0.7 H2 ADR generation pipeline as primary design
  principle):** ADRs are load-bearing substrate (hard requirement);
  README + DESIGN.md are optional inputs improving generation/atlas
  quality when available; tool extracts/operates from minimum-substrate
  (code patterns when only code present) and produces better output
  when more substrate available; quality scales with input richness.
  Applies to H5 doctor multi-dimension state-detection at v0.6
  (independently detects each substrate dimension; surfaces conditional
  guidance based on what's present); applies to H2 ADR generation at
  v0.7 (single pipeline accepting available substrate; descriptive
  when code-only; prescriptive when DESIGN.md substantive). Replaces
  earlier "two paths" (existing-repo Path A vs new-project Path B)
  framing with substrate-flexibility-as-input-dimension framing.
- **Substrate-generation-not-feature-completion cycle thesis:** v0.6
  cycle produces empirical substrate for v0.7 design work; v0.6
  doesn't ship feature-complete production tool. Cycle-weight
  discipline preserved through scope-bounded thesis-narrowing
  (matches v0.5 thesis-narrowing precedent).
- **Early-access cohort discipline:** Travis network with private
  invitations; controlled exposure; cohort-process tooling (cohort
  feedback template; tool-description observability; structured
  feedback shape isolating natural-routing failure modes from tool-
  description failure modes from missing-functionality failure
  modes). Cohort-process tooling carries forward to v0.7 trial
  execution + v1.0 launch as canonical inheritance per Item 6
  recruitment infrastructure shipping at v0.6.
- **Strategy B-with-explicit-launch-staging cycle architecture:** v0.6
  generates substrate; v0.7 designs against substrate + executes
  trial; v1.0 launches as production tool. Cycle-architecture decision
  resolved across 8-item debate phase + 2 reconsiders; locked at
  Phase 2.

### Stream A — Pipeline-mechanics (5 items)

artifact. Per Item 5 reconsider path β refined: install + doctor +

**A4 — `buildBundle` lazy-spawn (atlas-only mode).** Atlas-only
mode queries don't need adapter spawn (~500ms-per-query overhead
for no information gain in committed-atlas case). A4 lazy-spawns
adapter only when query needs LSP-live data (diagnostic resolution;
recently-edited file re-symbolization). Load-bearing for clean
init UX — first-query smoke test should not pay 500ms adapter-
spawn cost when atlas is committed. Surfaced v0.5-candidates.md
#4 from v0.4 Step 8 doctor work.

**A6 — Doctor script (deep LSP health check + multi-dimension
state-detection).** Reweighted load-bearing pipeline-step-1 per
Phase 1 inventory addition + Travis personal-notes substrate.
Doctor is gateway to all conditional setup paths; full
`initialize → didOpen → diagnostic-arrival → shutdown` LSP sequence
with actual symbol traversal catches adapter regressions doctor's
v0.5+ shallow check missed (e.g., gopls workspace-load failure on
`go.mod`-less directories). Plus H5 multi-dimension state-
detection produces state report driving setup walkthrough options;
NOT enforcement-routing per Travis personal-notes substrate.

**H5 — Doctor script multi-dimension state-detection logic.**
Cycle-emergent at Phase 1 inventory addition + Item 5 reconsider
correction. Detects ADRs / code / README / DESIGN.md substantive-
content-detection / language / git substrate independently
(per flexibility-as-feature design principle). State report drives
conditional guidance: existing-repo-with-ADRs path; existing-repo-
missing-ADRs path (explicit guidance: "ContextAtlas requires ADRs;
v0.6 doesn't auto-generate; please add ADRs manually then re-run
doctor"); new-project path (explicit guidance: "create README +
DESIGN.md per ADR-bootstrap pattern; v0.7 H2 ADR generation
pipeline will scaffold further"); etc. Substantive-content-
detection helps H2 ADR generation quality at v0.7; v0.6 doctor
provides detection without enforcement.

**A7 — Self-use ContextAtlas-as-MCP onboarding pipeline.** v0.6
cycle-thesis-primary deliverable. Per Item 5 reconsider path β
