## Editorial framing — production tool

v1.1 onward, ContextAtlas develops as a **production tool**, not a
research project. Cycle scope ships features production users need.
Benchmark substrate at the benchmarks repo persists as historical
record and ad-hoc empirical playground; it does not gate ships and
is not load-bearing for cycle-close.

Cycle-engineering discipline (Pattern 7 four-axis verification,
pause-and-surface vs verify-and-act, cross-role verification at
measurement-substrate entry) is how-we-work production-tool quality
discipline, not research methodology. Discipline carry-forward
substrate lives at [`v1_1-HANDOFF.md`](v1_1-HANDOFF.md).

**Concrete consequence.** Research items from
[`research/v1.1-candidates.md`](research/v1.1-candidates.md) are
**scrapped from the roadmap** (see §5). Cycle-discipline items
preserved at `v1_1-HANDOFF.md` as engineering discipline (not
features). Production-tool refinements from the candidate inventory
map into Arc 4 below.

## Roadmap shape — four arcs spanning v1.1-2.0

The roadmap is organized as four feature arcs. Every keeper item
from prior candidate inventories maps into an arc or a version slot;
every research item gets one explicit scrap line (§5) so nothing
floats as undifferentiated debt. Features lead; leftovers either
find a home or are named dead.

### Arc 1 — Multi-repo: architectural memory across a product family

**The load-bearing 2.0 thesis.** ContextAtlas evolves from "single-
repo architectural memory" to "architectural memory across a product
family." Three use cases drive the arc:

1. **API discovery** — lightweight app sessions surface backend
   atlas's endpoint inventory ("is there already an endpoint for X?")
2. **Cross-repo architectural awareness** — design-decision claims
   from sibling repos surface during development ("what auth pattern
   does the core app use?")
3. **Merge-safety / design-consistency** — pre-merge architectural-
   contradiction detection across repo boundaries (the 2.0 thesis;
   "warn me if this contradicts an ADR in another repo")

**Version slot decomposition:**

| Shape | Version slot | What it ships |
|---|---|---|
| Shape 1 — Federated query (asymmetric consumer-model) | v1.1.x post-v1.1.0 | Config + MCP retrieval-layer federation across N precomputed atlases; one consuming repo reads N read-only foreign atlases; ADR-01 additive amendment for repo-prefixed foreign symbol IDs (local stays unprefixed) |
| Shape 2 — Workspace as first-class concept | v1.2-v1.5 | `contextatlas.workspace.yaml`; workspace-aware doctor; CLI workspace commands; workspace becomes unit of scope for tool args |
| Shape 4 — Atlas-of-atlases (cross-repo decision substrate) | v2.0 | Higher-order substrate; umbrella ADR convention; cross-repo claim type; merge-safety / design-consistency tool surface |

Shape 3 (external-source consumption into local atlas) **rejected**
per cross-repo staleness-coupling argument; not on roadmap.

**Thesis-integrity invariant preserved.** All shapes stay inside
ADR-02 zero-query-time-API-call invariant. Each atlas remains
precomputed once per repo. Federation fans out *retrieval* at query
time across precomputed substrate; no extraction at query time.
Federation extends the substrate-locality model; doesn't break it.

### Arc 2 — Language adapter expansion (cohort-driven)

| Adapter | Version slot | Driver |
|---|---|---|
| C# (.NET) | v1.1.0 | Locked — see [`v1.1-SCOPE.md`](docs/cycles/v1_1/v1.1-SCOPE.md) |
| Rust | v1.2-v1.5 | Cohort demand; LSP via rust-analyzer; minimal PATH enrichment expected (rustup-managed) |
| Java | v1.2-v2.0 | Cohort demand; widest install variation (system JDK / jenv / sdkman / IDE-bundled JDK / Coursier); expect substantial PATH-enrichment work parallel to or wider than Ruby |
| Kotlin / Swift | v2.0+ | Mobile-dev cohort if surfaces; core-app dogfood case demonstrates value |

Pattern 7 four-axis discipline + adapter-authoring substrate per
[`docs/v1_1-INHERITANCE-SUBSTRATE.md`](docs/v1_1-INHERITANCE-SUBSTRATE.md)
applies to every cycle. Ruby v0.9 Stream A is the most recent
template (~1300 LOC adapter + 535 LOC doctor + 116 tests + ADR with
3-5 amendments expected for structurally-complex languages).

Each adapter ships as its own version (no multi-adapter cycles).
Cohort feedback gates ordering after .NET.

### Arc 3 — New claim sources (substrate breadth)

Current claim sources: ADR + docstring + commit message. Candidates
for v1.x:

| Source | Version slot | Rationale |
|---|---|---|
| DB schemas (SQL files, migration files, ORM models) | v1.2-v1.5 | Load-bearing for cross-repo data-design awareness; pairs with .NET backend; prereq for Shape 4 surfacing data-design contradictions; connects to v0.9 Stream A Ruby `db/migrate/**` exclude-pattern thread |
| PR descriptions | v1.2-v1.5 | Architectural intent often lives in PR descriptions, not commits; existing GitHub API access pattern reusable |
| README / CONTRIBUTING as separate claim class | v1.2+ | Currently absorbed into ADR-style extraction; may deserve own provenance + claim category |
| API specs (OpenAPI / Swagger) | v1.2-v1.5 | Pairs directly with multi-repo use case 1 (API discovery); .NET backend likely OpenAPI-instrumented; could surface endpoint claims with route + verb + request/response shape |

Each new claim source per [`CLAUDE.md`](CLAUDE.md) §Pipeline
Integration Discipline: PR must cross-reference precedent integration
(commit-message extraction is the v0.4 precedent for new sources
after docstring + ADR) + stage-by-stage symmetry-OR-divergence-OR-
not-applicable note.

## §7 Versioning model

Inherited from v0.7+ convention (substep-bounded ship-commits with
annotated tag bodies as canonical release-notes substrate; preserved
at v0.9.1 Stream B.3 with backfill alongside `CHANGELOG.md`
promotion):

- **vM.N.0** = cycle close ship (feature-bearing)
- **vM.N.x** (x ≥ 1) = substep-bounded follow-on ships within cycle
- Cycle scope authored per-cycle at
  `docs/cycles/v{M}_{N}/v{M}.{N}-SCOPE.md`
- Cycle-engineering knowledge cluster captured per-cycle at next-
  cycle HANDOFF append per Y-2 precedent

**v1.1 cycle anchors:**

- **v1.1.0** = .NET adapter ship (sole-focus per
  [`v1.1-SCOPE.md`](docs/cycles/v1_1/v1.1-SCOPE.md))
- **v1.1.x** = federation Shape 1 + production-engineering follow-
  ons
- **v1.2.0+** = next major theme per arc prioritization at v1.2
  cycle pre-planning
